AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.

## 심각도 정의

- **치명** — 아래 네 유형 중 하나에 해당하는 문제. 1건이라도 있으면 반려. 네 유형에 들지 않는 문제는 치명으로 올리지 않는다(경고 또는 제안).
  - 비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립
- **경고** — 지금 고치지 않아도 동작하지만 다음 변경에서 사고가 될 가능성이 있는 문제. 승인 여부는 리뷰어가 판단한다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했다(실행하지 않고 통과라고 쓰지 않는다).
- [ ] 실행 결과에 실패 · 오류가 0건이다.
- [ ] 새로 추가된 public 메서드마다 그 메서드를 호출하는 테스트가 1개 이상 있다. 접근자(getter · setter · 생성자 · record 컴포넌트 접근자)는 제외한다.
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없다.

## 2. 치명 이슈 0건

- [ ] (비밀값 노출) 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처 · 로그 출력에 리터럴로 들어 있지 않다.
- [ ] (데이터 손실) 데이터를 지우거나 덮어쓰는 코드가 새로 생겼다면 요청 문장에 그 내용이 들어 있다.
- [ ] (인증 우회) 인증 · 권한 검사를 없애거나 건너뛰는 경로(검사 삭제, 허용 경로 추가, CORS · 보안 설정 완화, Actuator 엔드포인트 노출 확대(`health` 외 공개, `exposure.include=*`))가 새로 생기지 않았다.
- [ ] (인증 우회) 새로 만든 조회 · 수정 경로는 요청자가 그 대상(학생 · 학급 · 과제)에 접근할 수 있는지 서버에서 확인한다. 경로로 들어온 ID 만 믿고 조회하지 않는다.
- [ ] (SQL 문자열 조립) SQL 을 `+` · `String.format` 으로 이어 붙여 만드는 곳이 없다(`:이름` + `@Param` 바인딩 사용). T-SQL 저장 프로시저 안에서도 `EXEC(@sql)` 처럼 이어 붙인 동적 SQL 이 없다(`sp_executesql` + 파라미터).

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청 문장으로 설명되지 않는 변경 줄은 모두, 요청 때문에 바뀐 파일 안의 import 추가 · 삭제 · 순서 정리뿐이다.
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 포함돼 있었다.

## 4. 컨벤션 준수

`[반려]` 항목이 하나라도 "아니오"면 이 기준은 미충족이다. `[경고]` 항목은 이슈 목록에 경고로만 적는다.

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했다(`convention-check` Skill 이 있으면 그 결과를 쓴다).
- [ ] `[반려]` (계층) 컨트롤러가 `*Repository` 타입을 import 하거나 필드 · 생성자 인자로 갖지 않고, 서비스만 호출한다.
- [ ] `[반려]` (빈 catch) 비어 있는 `catch`, 로그만 남기고 끝나는 `catch` 가 없다.
- [ ] `[반려]` (임시 출력) `System.out` · `System.err` · `printStackTrace()` · `console.log` 가 없다.
- [ ] `[반려]` (금지 사항) 팀 `CLAUDE.md` 의 금지 사항을 어긴 곳이 없다.
- [ ] `[반려]` (요청 DTO) 요청 본문을 `@Entity` 에 직접 바인딩하지 않고, 받을 필드만 정의한 `record` DTO 로 받는다.
- [ ] `[경고]` (네이밍) 새 이름이 기존 관례(`XxxResponse.from(entity)`, `@DisplayName("메서드명: 기대 동작")` 등)를 따른다.
- [ ] `[경고]` (개인정보 출력) 로그 · 응답 · 오류 메시지에 학생 식별자(`STU-<숫자>`) · 이메일을 원문으로 남기지 않는다.
- [ ] `[경고]` (입력 검증) 외부 입력을 서버에서 검증한다(타입 · 범위 · 길이 · 허용 목록).
- [ ] `[경고]` (오류 응답 노출) 오류 응답에 스택트레이스 · 예외 메시지 원문 · SQL 오류 문구가 담기지 않는다.
- [ ] `[경고]` (그 밖) 위 항목에 없는 `CLAUDE.md` 코딩 컨벤션을 어긴 곳이 없다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
