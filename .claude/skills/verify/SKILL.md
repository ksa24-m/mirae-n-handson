# 머지 전 검증

검증 대상: $ARGUMENTS

- 인자가 비어 있으면 `git diff upstream/main...HEAD` 를 대상으로 삼는다.
- 인자가 `.patch` 파일이면 그 patch 를 대상으로 삼는다.
- 승인 체크리스트는 저장소 루트의 `templates/approval-checklist.md`, 절차 원문은 저장소 루트의 `templates/verification-loop.md` 다. 항목은 이 파일에 옮겨 적지 않고 매번 그 파일을 읽어 쓴다.

## 원칙

- 이 세션은 리뷰 세션이다. 판정과 수정 방향만 보고하고 코드는 고치지 않는다.
- 테스트 출력은 통과 · 실패 수와 실패한 테스트 이름만 남긴다. 전체 로그를 대화에 싣지 않는다.

## 절차

### 1. 요청 범위 확인

- 무엇을 요청했는지 한 문장으로 확인한다. patch 파일이면 머리말의 `Subject:` 가 요청 문장이다(`head -n 20 <patch>`).
- 요청 문장이 주어지지 않았으면 **판정하지 말고** 먼저 사용자에게 묻는다. 답을 받기 전에는 2단계로 넘어가지 않는다.

### 2. 변경 파일 목록과 diff 읽기

- git 범위: `git diff --stat <범위>` 로 목록을 먼저 보고, 파일마다 `git diff <범위> -- <파일>` 을 읽는다.
- patch 파일: `git apply --stat <patch>` 로 목록을 뽑고 patch 본문의 파일별 diff 를 읽는다.
- 줄번호는 변경 후 파일 기준으로 적는다. patch 는 hunk 머리(`@@ -a,b +c,d @@`)의 `+c` 에서 센다.

### 3. 체크리스트 대조

- 저장소 루트의 `templates/approval-checklist.md` 를 읽는다.
- 항목마다 `충족` / `미충족` / `확인 필요` 중 하나로 표시한다.
- 컨벤션 항목은 저장소 루트의 `CLAUDE.md` 코딩 컨벤션 · 금지 사항과 대조한다. 심각도는 체크리스트의 심각도 정의(치명 / 경고 / 제안)를 따른다.

### 4. 테스트 실행

2단계 목록에서 바뀐 폴더의 테스트만 실행한다.

| 바뀐 폴더 | 명령 (저장소 루트 기준) |
|---|---|
| `modern/api` | `cd modern/api && ./gradlew test` |
| `modern/web` | `cd modern/web && npm test` |
| 이관 코드(레거시 동작을 `modern/api` 로 옮긴 변경) | `cd characterization && npm test` (레거시 대상), `cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상) |

- 출력은 요약 줄만 걸러서 본다. 예:
  - gradle: `./gradlew test --console=plain 2>&1 | grep -E "tests completed|FAILED|BUILD (SUCCESSFUL|FAILED)"`
  - vitest: `npm test 2>&1 | grep -E "Test Files|Tests |FAIL"`
- 기록은 실행 명령, 통과 · 실패 수, 실패한 테스트 이름만 남긴다.
- patch 파일이 대상이면 리뷰 브랜치에 적용한 뒤 실행한다(저장소 루트의 `vendor-prs/README.md` 의 "리뷰 브랜치에 적용하기"). 적용할 수 없으면 실행하지 않은 것으로 적는다.
- 실행할 수 없었으면(`ECONNREFUSED`, 서버 꺼짐, 의존성 미설치) 그 사실과 원인을 적고, 사람에게 기동을 요청한다(예: `docker compose --profile php up -d`, `cd modern/api && ./gradlew bootRun`). 이 경우 "테스트 통과"는 `미충족` 으로 둔다.

### 5. 승인 기준 판정

- 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 판정한다.
- 넷 다 충족이면 승인, 하나라도 미충족이면 반려다.
- 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 본 뒤 출력한다.

## 출력 형식 (순서 고정)

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수, 실패한 테스트 이름 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 이슈 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|
| 1 | 치명 / 경고 / 제안 | modern/api/.../Xxx.java:42 | 어긴 규칙 · 코드 인용 | 고칠 방향 한 줄 |

확인 필요
- 무엇을 확인해야 하는지 한 줄씩
```

- 이슈가 없으면 표 대신 "이슈 없음"이라고 적는다.

## 하지 말 것

- 코드를 수정하지 않는다. 고치기 시작하면 그 순간 만든 쪽이 된다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- 요청 범위를 모르는 상태에서 "요청 범위 이탈 없음"을 충족으로 표시하지 않는다.
