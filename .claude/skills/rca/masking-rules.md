# RCA 리포트 마스킹 규칙

리포트를 `docs/rca/` 에 저장하기 전에 아래 규칙을 본문 · 표 · 코드 블록 · 명령 전부에 적용한다.
별칭 대응은 작업 중에만 기억하고 파일로 남기지 않는다.

| 종류 | 대상 | 바꾸는 방법 | 예 |
|---|---|---|---|
| IP 주소 | IPv4 · IPv6 전체, `host:port` 의 host, 일부 옥텟(`3.12` 같은 뒷자리)까지 | 구분이 필요하면 **역할 별칭**, 구분이 필요 없으면 `<IP>` | `API-1`, `API-2`, `교사단말A` ~ `교사단말D` |
| 이메일 | `user@domain` 형태 전부 | `<EMAIL>` | |
| 학생 식별자 | `STU-<숫자>`, 이름 · 학번 등 학생을 가리키는 값 | 구분이 필요하면 `학생A` · `학생B` …, 아니면 `<STU>` | `reason=학생A 결석으로 재배포` |
| 토큰 · 키 | Bearer · JWT · 세션 ID · API 키 · `Authorization` 헤더 값 · 쿼리스트링의 `token=` 등 | `<TOKEN>` (헤더 이름은 남기고 값만) | `Authorization: Bearer <TOKEN>` |
| 비밀번호 · 접속 정보 | `password=`, `pwd=`, 접속 문자열(`jdbc:…user:pass@`)의 자격 증명 | `<SECRET>` (키 이름은 남긴다) | `password=<SECRET>` |

## 역할 별칭 규칙

- 같은 원본 값은 리포트 전체에서 항상 같은 별칭이다. 다른 원본 값에 같은 별칭을 쓰지 않는다.
- 별칭은 로그에서 드러난 역할로 짓는다: 서버는 `API-1` · `API-2` · `DB-1`, 클라이언트는 `교사단말A` · `학생단말A` 처럼 쓰고, 처음 등장한 순서대로 A · B · C 를 붙인다.
- 역할을 알 수 없으면 `호스트A` 처럼 중립적으로 쓴다. 추측한 역할을 별칭에 넣지 않는다.
- 로그 원문 인용과 실행 명령 안의 값도 같은 별칭으로 바꾼다. 그래서 명령이 그대로 실행되지 않을 수 있다는 점을 문서 끝에 적는다.

## 적용 후 확인

- 저장 직전에 리포트 본문을 다시 검사해 남은 것이 없는지 본다(예: IPv4 `\b[0-9]{1,3}(\.[0-9]{1,3}){3}\b`, `@`, `STU-[0-9]`, `Bearer`, `password`).
- 문서 끝에 한 줄로 남긴다: `마스킹 적용: IP 주소 N건(역할 별칭 K종) · 이메일 N건 · 학생 식별자 N건(별칭 K명) · 토큰 · 세션 ID · API 키 · Authorization N건 · 비밀번호 · 접속 문자열 N건`
