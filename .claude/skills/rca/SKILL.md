# 장애 RCA 리포트

대상은 `incident-logs/$ARGUMENTS/`, 결과는 `docs/rca/$ARGUMENTS.md` 다.
인자가 비었거나 폴더가 없으면 `incident-logs/` 의 폴더 목록을 보여 주고 멈춘다.

## 절차 (순서 고정)

1. **수집 범위** — 파일을 통째로 읽지 않는다. `wc -l` · `head` · `tail` · `grep -c` · `awk` 집계로 먼저 본다.
   - 파일별 줄 수, 첫 · 마지막 기록(원문), 시각 형식, 타임존을 표로 만든다.
   - 오프셋이 없는 로그는 다른 파일과 같은 사건을 초 단위로 맞춰 타임존을 판단하고 근거를 적는다(예: 슬로 로그 epoch ↔ `# Time`).
   - 이상 신호를 분 단위로 세어 시작 · 끝을 잡고, 앞뒤 여유와 비교용 평소 구간을 정한다. 이 단계에서는 원인을 말하지 않는다.
2. **타임라인** — 수집 범위 안의 사건을 한 시간축(KST)으로 합친다.
   - **모든 줄에 `파일:줄번호`** 와 원문 인용을 붙인다. 해석은 넣지 않는다.
   - 파일이 다르고 차이가 시각 정밀도 이내면 **(선후 불확실)** 로 표시한다.
   - 반복 메시지는 "첫 발생 · 이후 분=건수" 로 묶는다. 가장 많은 오류 이전 구간을 따로 본다.
3. **가설** — 계층(코드 · DB · 트래픽 · 인프라 등)이 다른 가설을 **2개 이상** 세운다.
   - 먼저 가장 많이 나온 메시지를 "증상" 표로 분리하고, 각 메시지가 알려 주는 것과 알려 주지 않는 것을 적는다.
   - 가설마다 지지 근거, **반증 조건**(무엇이 보이면 틀린 것인가), **확인 방법**(실행할 명령)을 쓴다.
4. **반증 · 판정**
   - 로그로 확인할 수 있는 반증 조건부터 실제로 실행하고, 명령과 결과를 실행 기록으로 남긴다. 1차 판정: 유지 · 기각 · 판단 불가(필요한 로그 명시).
   - 유지된 가설을 로그에 찍힌 클래스의 코드와 설정 파일(`파일:줄번호`)에 대조한다. 읽은 값만 적고, 저장소 코드가 배포본과 같다는 전제는 전제로 밝힌다.
   - 최종 판정: 채택 1개와 기각 사유. 근본 원인이 아닌 가설이라도 촉발 요인 후보면 그렇게 남긴다.
5. **리포트 작성** — 다음 절을 이 순서로 쓴다.
   - 요약(무슨 일 · 원인 · 확신 수준 · 조치), 수집 범위, 타임라인, 가설과 검증
   - 원인(직접 원인 인과 순서 + 배경 원인), 근거 로그 줄(`파일:줄번호` + 원문)
   - 수정안(지금 적용, 코드는 고치지 않고 제안만), 재발 방지(구조)
   - 모니터링 항목(지표 · 임계값 · 이번에 울렸을 시각 · 첫 5xx 대비)
   - 확인하지 못한 것(이유 · 다음을 위해 남겨야 할 로그)
6. **마스킹** — 리포트를 저장하기 전에 `masking-rules.md` 의 규칙을 적용한다. 문서 끝에 종류별 적용 건수 한 줄을 남긴다.

각 단계가 끝나면 한 줄 요약을 보고한다. 리포트는 마스킹을 적용한 뒤에만 파일로 쓴다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 인용 전에 `sed -n '<줄>p'` 로 원문을 다시 확인한다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 그것은 증상이다.
- 원본 로그(`incident-logs/`)와 소스 코드를 수정하지 않는다.
- 마스킹 대응표(원본 ↔ 별칭)를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
- 확인하지 않은 것을 확인한 것처럼 쓰지 않는다. 모르면 "확인하지 못한 것" 에 넣는다.
